# A05 — Injection (инъекции)

**Статус:** ✅ готово

## О чём лаба
Сайт вымышленной авиакомпании **Skyline**: поиск рейсов, результаты, карточка рейса с бронированием, «Мои поездки», вход/регистрация и админка с инструментом проверки узла аэропорта. Интерфейс многоязычный (EN / RU / UZ, переключатель в шапке). Ввод пользователя попадает в SQL-запросы и в командную строку, поэтому его можно превратить в код: **SQL-инъекция** и **command injection**.

## Чему научитесь
- Понимать, как данные пользователя меняют смысл SQL-запроса
- Обходить вход, вскрывать скрытые данные и вытаскивать чужие записи через SQL-инъекцию (на учебном приложении)
- Понимать, чем опасна склейка строки рядом с `os.popen`
- Защищаться: параметризованные запросы, белые списки ввода, отказ от оболочки

## Запуск

```bash
docker compose up --build
```

| Версия | Адрес |
|--------|-------|
| vulnerable (уязвимая) | http://127.0.0.1:8041 |
| fixed (исправленная) | http://127.0.0.1:8042 |

Без Docker:

```bash
pip install -r vulnerable/requirements.txt   # для fixed: fixed/requirements.txt
python vulnerable/app.py                     # http://127.0.0.1:5000
```

> ⚠️ Приложение уязвимо специально. Запускайте только локально и не публикуйте в интернет.
> Проверка узла использует `ping` (Linux/macOS/Docker) — на Windows обычная проверка покажет ошибку, но упражнение с command injection там всё равно работает: используйте `&` вместо `;`.

## Задание
Тестовый аккаунт: `alice` / `alice123`. Страницы сайта удобнее открывать в браузере: консоль лабы — на `/ui`.

1. Войдите как `admin`, **не зная пароля** (`POST /login`). В `/me` админа есть флаг.
2. Через поиск рейсов (`GET /flights?from=...&to=...`) покажите **чартерный рейс**, скрытый от обычных пассажиров, откройте его и найдите флаг.
3. Через тот же поиск достаньте из таблицы `users` секрет администратора (флаг `FLAG{...}`).
4. Получите права администратора (п. 1) и выполните свою команду через проверку узла аэрпорта (`POST /admin/check`), чтобы прочитать флаг из окружения процесса.
5. Повторите всё на **fixed**-версии и объясните, почему не работает.
6. Сравните `vulnerable/app.py` и `fixed/app.py`: места исправлений помечены `FIX`.

## Подсказки
1. Что произойдёт, если в имя пользователя поставить одинарную кавычку `'`? Видно ли ошибку SQL?
2. В SQL `--` начинает комментарий. Что можно закомментировать в запросе входа?
3. В запросе поиска есть условие `hidden = 0`. Как его нейтрализовать?
4. `UNION SELECT` добавляет строки из другой таблицы, но число столбцов должно совпасть с исходным запросом (посчитайте столбцы в `SELECT`).
5. Проверка узла собирает команду из поля хоста. Какой разделитель команд (`;` в Linux/macOS, `&` в Windows) позволит выполнить лишнюю команду и где в процессе лежит флаг?

Полное решение со спойлерами: [SOLUTION.ru.md](./SOLUTION.ru.md)

## Как защититься
- **SQL:** параметризованные запросы (`?` и передача значений отдельно), а не склейка строк
- **Команды:** никогда не собирать shell-команду из пользовательского ввода — использовать список аргументов без оболочки и белый список символов (например, `^[A-Za-z0-9.-]+$`)
- **В глубину:** не показывать пользователю тексты ошибок БД, ограничивать длину и формат ввода, держать права учётной записи БД минимальными
- Считать каждый ввод (параметры HTTP, заголовки, имена файлов) недоверенными данными, а не кодом
