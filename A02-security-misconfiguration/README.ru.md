# A02 — Security Misconfiguration (небезопасная конфигурация)

**Статус:** ✅ готово

## О чём лаба
**Сайт кофейни Lumière Café** на Flask: лендинг, меню со страницами блюд и вход для персонала. Интерфейс доступен на **английском, русском и узбекском** — переключатель EN / RU / UZ в шапке сайта, выбор запоминается в cookie и задаётся параметром `?lang=en|ru|uz`. Выглядит и работает как обычный сайт небольшого заведения, но развёрнут с типичными ошибками настройки: пароль по умолчанию, лишние открытые файлы, подробные ошибки и отсутствие защитных заголовков. Кода-эксплойтов здесь нет: уязвимости это именно **неправильные настройки**.

## Чему научитесь
- Находить небезопасные настройки в приложении
- Понимать, чем опасны подробные ошибки и забытые файлы (`.env`, бэкапы)
- Настраивать защитные HTTP-заголовки и отдавать наружу только нужное

## Что за сайт

| Страница | Адрес | Примечание |
|----------|-------|------------|
| Главная | `/` | В браузере открывается сайт; `curl` получает короткое JSON-описание API |
| Меню | `/menu` | Все блюда по категориям |
| Блюдо | `/menu/<id>` | например `/menu/4` |
| Вход для персонала | `/admin` | Форма отправляется на `POST /login` |
| Консоль лабы | `/ui` | Список эндпоинтов, примеры запросов, ответы (ссылка в подвале сайта) |

## Запуск

```bash
docker compose up --build
```

| Версия | Адрес |
|--------|-------|
| vulnerable (уязвимая) | http://127.0.0.1:8011 |
| fixed (исправленная) | http://127.0.0.1:8012 |

Обе версии показывают один и тот же сайт кофейни — отличается только конфигурация. Откройте в браузере http://127.0.0.1:8011/ и пользуйтесь сайтом как обычный посетитель.

Без Docker:

```bash
pip install -r vulnerable/requirements.txt
python vulnerable/app.py   # http://127.0.0.1:5000
```

> ⚠️ Приложение уязвимо специально. Запускайте только локально и не публикуйте в интернет.

## Задание
Найдите в vulnerable-версии **четыре** ошибки конфигурации (в каждой спрятан флаг или признак):

1. Войдите в панель кофейни администратором, не зная пароля.
2. Получите секретные данные приложения, не имея доступа к серверу.
3. Заставьте приложение выдать лишнюю техническую информацию.
4. Проверьте HTTP-заголовки ответа: каких защитных заголовков не хватает и что лишнее выдаёт сервер?

Затем повторите проверки на fixed-версии. Пароль админа в fixed генерируется при старте: `docker compose logs fixed` (или задайте свой через переменную `ADMIN_PASSWORD`).

## Подсказки
1. Какие логин и пароль часто остаются «по умолчанию»? Форма для персонала — на `/admin`.
2. Что делает маршрут `GET /files/<имя>` и какие файлы лежат рядом с `app.py`? Все маршруты приложения перечислены в консоли `/ui`.
3. Что вернёт `GET /menu/abc`? (номер блюда ожидается числом)
4. Используйте `curl -i`, чтобы увидеть заголовки.

Полное решение со спойлерами: [SOLUTION.ru.md](./SOLUTION.ru.md)

## Как защититься
- Менять пароли по умолчанию, секреты хранить в окружении, а не в файлах рядом с кодом
- Отдавать наружу только каталог со статикой, а не корень приложения
- Показывать пользователю нейтральную ошибку, подробности писать в серверный лог
- Добавлять защитные заголовки и убирать лишние баннеры с версиями
- Регулярно проверять конфигурацию автоматическими сканерами
