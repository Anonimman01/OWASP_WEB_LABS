# A01 — Broken Access Control (нарушение контроля доступа)

**Статус:** ✅ готово

## О чём лаба
Корпоративный HR-портал (**TestLab HR**) с тремя пользователями (`alice`, `bob`, `admin`): сотрудники подают заявки в HR и смотрят справочник коллег, у администратора есть отдельный раздел. Вход есть, но сервер не везде проверяет, **кому** принадлежит ресурс и **какая роль** у пользователя.

## Чему научитесь
- Находить IDOR (подмена идентификатора ресурса в запросе)
- Отличать аутентификацию («кто вы») от авторизации («что вам можно»)
- Проверять права на сервере при каждом запросе, по принципу «запрещено по умолчанию»

## Запуск

```bash
docker compose up --build
```

| Версия | Адрес |
|--------|-------|
| vulnerable (уязвимая) | http://127.0.0.1:8001 |
| fixed (исправленная) | http://127.0.0.1:8002 |

Без Docker:

```bash
pip install -r vulnerable/requirements.txt
python vulnerable/app.py   # http://127.0.0.1:5000
```

> ⚠️ Приложение уязвимо специально. Запускайте только локально и не публикуйте в интернет.

Откройте адрес в браузере, и вы увидите портал TestLab HR. Кнопка **Lab** (справа внизу) открывает панель лабы: задания, которые отмечаются сами, подсказки и журнал запросов портала. Консоль сырого API лежит на `/ui`; `curl` и Postman по-прежнему получают JSON с `/`.

## Задание
Тестовый аккаунт: `alice` / `alice123`.

1. Войдите как `alice` (`POST /login`, JSON с `username` и `password`).
2. Прочитайте заявку, которая принадлежит **админу** (в ней спрятан флаг `FLAG{...}`; в портале заявки открываются по адресу `#/requests/<id>`).
3. Откройте админский раздел `/admin/users`, не будучи админом (в портале: `#/admin`).
4. Повторите те же запросы на **fixed**-версии и убедитесь, что доступ закрыт.
5. Сравните `vulnerable/app.py` и `fixed/app.py`: места исправлений помечены `FIX`.

## Подсказки
1. Откройте `GET /api/notes`: какие `id` у ваших заявок?
2. Что вернёт `GET /api/notes/<id>`, если подставить чужой `id`?
3. Какие проверки делает сервер перед `GET /admin/users`? Портал скрывает от вас пункт меню, но останавливает ли это сервер?

Полное решение со спойлерами: [SOLUTION.ru.md](./SOLUTION.ru.md)

## Как защититься
- Проверять владельца ресурса и роль пользователя **на сервере**, для каждого запроса
- Запрет по умолчанию: доступ только там, где он явно разрешён
- Не полагаться на то, что «пользователь не знает URL»
